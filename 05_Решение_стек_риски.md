# Решение: стек, архитектура, риски

Проектируем под три жёстких ограничения, которые уже известны:
**26 часов работы · нет интернета на Соловках · 70 % данных без географической привязки.**

---

## 1. Суть решения одной фразой

> **Статический офлайн-сайт из одной папки**: HTML + CSS + чистый JS, данные — JSON, сгенерированный из Excel музея скриптом на Python. Запускается двойным кликом с флешки, тот же билд открывается в браузере киоска и на сайте музея.

Ни сервера, ни базы данных, ни сборки, ни лицензий, ни интернета.

---

## 2. Почему именно так (и почему не иначе)

| Вариант | Вердикт |
|---|---|
| **Статика: HTML/CSS/JS + JSON** | ✅ **выбираем.** 0 ₽, работает офлайн из `file://`, правится любым участником, живёт в киоске и в вебе одним билдом |
| Leaflet + OpenStreetMap | ❌ тайлы тянутся из сети. На Соловках карта будет серым квадратом |
| React / Vue / Next.js | ❌ нужен `npm install` → нужен интернет. Сборка ломается — чинить негде. Выигрыша на 16 точках нет |
| Tilda / Wix / Readymag | ❌ подписка, только онлайн, отдать музею нельзя |
| Unity / Unreal (киоск-приложение) | ❌ недели работы, вес в гигабайтах, обновлять сможет только программист |
| Django/PostGIS + админка | ❌ нужен сервер и сисадмин. У музея их нет |
| ArcGIS / Яндекс.Карты API | ❌ ключи, лимиты, интернет, деньги |
| PowerPoint / PDF-презентация | ❌ это не интерактивная карта, бриф не закрыт |

### Три технических решения, которые надо принять осознанно

**1. Данные подключаются как `<script>`, а не через `fetch()`**
```html
<script src="data/data.js"></script>   <!-- window.DATA = {...} -->
```
`fetch('data.json')` из `file://` блокируется CORS — сайт откроется пустым. С обычным `<script>` всё работает и с флешки, и с сайта. Это единственная неочевидная деталь, на которой такие проекты обычно горят.

**2. Карта — SVG, а не растр с тайлами**
16 точек, никакого зума по уровням не нужно. SVG: чёткий на любом экране (в том числе 4K-панели), красится в палитру музея одной переменной CSS, весит килобайты, точки — обычные DOM-элементы с `click` и `:focus`.
Подложка — **историческая или стилизованная карта архипелага из фондов музея** (растр `.webp`), сверху слой SVG-меток. Если музей подложку не даст — рисуем схематичную карту сами в Inkscape/Figma по обводу береговой линии.

**3. Excel остаётся мастер-источником**
```
Spisok_po_mestam_3.xlsx  →  build.py (openpyxl)  →  data/data.js
```
Музей продолжает вести привычную таблицу. Обновление карты = положить новый Excel и запустить один файл. **Это то, что превращает студенческий проект в переданный музею продукт.**

## 3. Архитектура интерфейса

Из аудита данных следует главное решение: **карта не может быть единственным входом** — она покажет 30 % материала.

```
┌───────────────────────────────────────────────────┐
│  ЭКРАН ПОКОЯ (attract)                            │
│  «411 имён. Соловецкий лагерь особого назначения» │
│  Медленная смена имён/фото. Касание → домой       │
└───────────────────────────────────────────────────┘
                        ↓ касание
┌──────────────────────┬────────────────────────────┐
│   🗺 КАРТА           │   📖 ВСЕ ИМЕНА             │
│   16 мест            │   411 персоналий           │
│   размер точки =     │   поиск · по сану ·        │
│   число людей        │   по алфавиту              │
└──────────────────────┴────────────────────────────┘
        ↓                          ↓
┌──────────────────────┐  ┌────────────────────────┐
│ КАРТОЧКА МЕСТА       │  │ КАРТОЧКА ЧЕЛОВЕКА      │
│ название, история,   │→ │ имя, сан, годы,        │
│ фото, N человек,     │← │ места (кликабельны),   │
│ список имён          │  │ ИСТОЧНИК, фото         │
└──────────────────────┘  └────────────────────────┘
```

**Обязательный элемент — «Место не установлено, 287 человек».**
Не прячем. Наоборот: это честное высказывание о состоянии знания и, по сути, главный
смысл экспозиции — большинство судеб не восстановлено. Формулировка для музея:
*«О 287 из 411 известно, что они прошли через соловецкие лагеря, но где именно —
пока не установлено. Исследование продолжается».*

В итоге эта строка стоит **во вкладке «Все имена», а не на карте**: по сути это фильтр
реестра, а на карте должна быть только карта.

### Экран покоя (attract loop) — не украшение
Через 90 секунд бездействия киоск возвращается на стартовый экран. Без этого через час работы экспозиции на экране будет висеть чужая открытая карточка, и следующий посетитель не поймёт, что это. Обязательный пункт приёмки.

## 4. Состав продукта

```
solovki-map/
├── index.html
├── css/style.css              ← вся палитра через CSS-переменные
├── js/
│   ├── app.js                 ← роутинг между экранами
│   ├── map.js                 ← клики по SVG-точкам
│   ├── registry.js            ← поиск и фильтры по 411 именам
│   └── idle.js                ← возврат на экран покоя
├── data/
│   ├── data.js                ← window.DATA (persons + places + glossary)
│   └── build.py               ← Excel → data.js
├── assets/
│   ├── map-base.webp          ← подложка карты
│   ├── map-points.svg
│   ├── photos/                ← фото персоналий (фонды музея)
│   └── fonts/                 ← PT Serif / PT Sans, локально
└── ДЛЯ_МУЗЕЯ.md               ← инструкция по обновлению
```

Ожидаемый вес: **менее 20 МБ** с фотографиями. Влезает на любую флешку, открывается мгновенно.

### Функциональный минимум и что сверху

**MUST (защищаем это — реально за 26 часов):**
- карта архипелага, 16 точек + «место не установлено»
- карточка места: справка, число людей, список имён
- карточка человека: имя, сан, годы, места, **источник**
- реестр всех 411 с поиском и фильтром по сану
- глоссарий терминов (закрывает барьер ЦА из брифа)
- экран покоя, полностью офлайн

**SHOULD (если останется время):**
- фильтр по годам, счётчики на точках

**Сделано сверх минимума:**
- карта архипелага и материкового берега у Кеми из данных OpenStreetMap
- зум до 24× с панорамой и щипком, без потери резкости
- масштаб до 24×, слой из 539 озёр, чтобы на приближении было что разглядывать
- группировка близких точек с распадом при зуме, потолок размера кружка
- несколько снимков на карточку с лентой миниатюр, просмотр во весь экран
- подписи авторства, даты и лицензии у каждого снимка
- колонка `parent`: место внутри места вместо спора за одну точку
- автоматическая раскладка подписей: четыре позиции, скрытие только при нехватке места
- режим разметки: перетаскивание меток и добавление новых мест кликом
- светлая тема одним атрибутом, вместе с подменой карты
- фото в карточках по имени файла, устойчивые идентификаторы людей
- поля `about` и `work` у мест

**COULD (не начинать, пока нет MUST):**
- временная шкала 1923–1939, QR-код на веб-версию «унести с собой», печать справки

Единственная возможная статья расходов — сенсорная панель, если у музея её нет. Это решение музея, не наше; на защите показываем на своём ноутбуке.

## 6. Риски

### 🔴 Критические

**Р1. Нет интернета на Соловках.**
В памятке участника прямо: *«Связь: заранее предупредите родных об ограниченной связи»*. Это значит: не будет ни `npm install`, ни Google Fonts, ни поиска по Stack Overflow, ни скачивания карт.
→ **Митигация: всё скачивается СЕГОДНЯ** (см. чек-лист ниже). Стек выбран так, что после выезда не нужно ничего доустанавливать.

**Р2. Данные не готовы к тому, чтобы быть картой.**
70 % без места, 83 % без источника, Секирная (41 человек) отсутствует целиком.
→ Архитектура «карта + реестр»; честные пометки «сведения уточняются»; цифры показать заказчику **на первой встрече**, а не на защите.

**Р3. Неизвестно железо в зале № 2.**
Фото пространства к брифу не приложены. Разрешение, ориентация (портрет/ландшафт), ОС, наличие ПК, тач или мышь — всё неизвестно.
→ День 1: сфотографировать, замерить, записать разрешение. Вёрстка адаптивная от 1280×720 до 4K, портрет и ландшафт. **Резерв: защита на своём ноутбуке.**

**Р4. Два пустых дня подряд — 28 и 29 августа.**
Между 27.08 вечером и 30.08 утром работы не будет вообще.
→ **Заморозка объёма вечером 27.08.** Всё, что не в MUST к этому моменту, — не делаем. 30-е оставляем на сборку и защиту.

### 🟠 Существенные

**Р5. Права на фотографии.**
Лагерные снимки и портреты — фонды музея, Госкаталог, семейные архивы. Использовать «найденное в интернете» нельзя.
→ Только то, что музей передаст письменно, с фондовыми номерами. План Б: карточки без фото, типографика вместо изображений — на тему гонений это работает даже сильнее.

**Р6. Тон и этика.**
Тема — репрессии и мученичество. Любая «игровая механика», яркая палитра, анимации-подпрыгивания, «достижения» — провал у заказчика.
→ Сдержанная типографика, приглушённая палитра, никаких звуков, никаких соревновательных элементов. Все формулировки интерфейса согласовать с А. П. Яковлевой. Возрастная маркировка 16+.

**Р7. Ошибки в санах и статусе канонизации.**
`сщмч` (священномученик) и `прмч` (преподобномученик) — не синонимы; «еп.» → «архиеп.» → «митр.» менялись во времени; в таблице уже есть опечатки («архепископ», «Константнин»).
→ Справочник санов на ~15 значений, сверка с ПСТГУ и с музеем. **Ни одного сана «по догадке».**

**Р8. Архивно-следственные дела.**
В источниках — дела Архива УФСБ по Архангельской обл. (№ П-14803, № П-3021).
→ Публикуем только то, что уже опубликовано музеем. Ссылка в карточке — на издание, а не на дело.

**Р9. Заказчик изменит требования.**
Четыре раздела брифа не заполнены (что запомнить, дизайн, референсы, ограничения по стилю).
→ Макет показать **26.08** (это день 3, «варианты решений» по дорожной карте) и зафиксировать письменно, хоть в чате. Позже 27-го правки не принимаем.

### 🟡 Управляемые

**Р10. Пятеро с разным уровнем.** → Роли с первого дня: данные / карта и дизайн / фронтенд / тексты и глоссарий / защита и документация. Один файл — один человек, чтобы не конфликтовать без git.

**Р11. Посетитель «выйдет» из приложения.** → Браузер в kiosk-режиме, отключить контекстное меню, выделение текста, перетаскивание, F11/Alt+Tab по возможности.

**Р12. Некому поддерживать после школы.** → `ДЛЯ_МУЗЕЯ.md` + трёхминутная видеозапись «как обновить данные». Без этого продукт умрёт к следующему сезону.

> Закрыто: в приложении есть панель музея (удержание заголовка две секунды → вкладка «Данные»).
> Сотрудник правит **всё, что видит посетитель** — персоналии, места, вид меток,
> фотографии — и сохраняет кнопкой, **без терминала и без программиста**.
> Источником правды стал `persons.csv`, а не Excel, иначе правки затирались бы
> при каждой пересборке. Терминал нужен только чтобы вычитать новый Excel музея.

**Р13. Тексты историко-церковной части.** → Мы не историки Церкви. Все справки по местам и терминам пишутся из перечисленных изданий с постраничными ссылками и вычитываются музеем.
